# 原生灰字建议接口核验

核验日期：2026-11-07。对象为本机正在运行的官方 Windows 桌面包
`OpenAI.Codex_26.1103.3517.0_x64__2p2nqsd0c76g0`。
结论仅适用于已检查的版本和读取通道，不代表未来官方版本不会提供接口。

当前状态：**Web / Android 尚未同步原生灰字建议**。没有调用生成接口补出另一条建议，
也没有为此启动执行器或发送消息。本次只补充接口核验记录和禁止生成的回归测试，
不发布新的客户端版本。

## 要求

读取官方桌面已经生成的同一条建议，保持其原文和所属会话、来源轮次。
Web 按 Tab、Android 点击接受，均只填入本地可编辑草稿；发送仍由用户另行操作。
用户自行输入时保留自己的内容，不用建议覆盖草稿。

官方 [Composer Predictions 说明](https://learn.chatgpt.com/codex/features/composer-predictions)
介绍了灰字及 Tab 接受行为；该产品说明不能证明第三方拥有读取缓存的接口。
生成预测不占官方使用限额或 credits，也不等于可以将第三方额外生成请求视为同一功能。

这些结果缩小了问题范围，但不能证明已检查的 6 个会话当时都显示了灰字。
判断“尚不能同步”的依据同时包括接口定义、通知初始化、缓存服务和现场快照，
不单凭一次空结果推断接口不存在。
现场原始字段扫描限制为 8 层、30,000 个节点，数组取最后 2 项，不输出消息、会话 ID 或账户值；
轮次计数另从现有客户端投影取得。没有对官方进程内存、浏览器配置库或全部运行日志做遍历。

## 不能用于读取的入口

- `requestUserMessagePrediction` 内部使用 `fetchQuery`；未命中缓存会运行预测。
  同时会移除该会话其他轮次的缓存，不能当作无副作用读取调用。
- 当前官方灰字生成路径调用 `thread/sample`，其结果返回给内部服务，再存入内存缓存。
  重新调用会形成另一次采样，不能保证取得屏幕上的同一条建议。
- 实验性的 `thread/prediction/request` 是请求预测的入口，不是已验证的缓存查询。
  仅知道 `threadId` 和 `sourceTurnId` 不构成调用它的理由。

上述三个生成入口均未调用。CXPalm 的原生 IPC 白名单继续拒绝这些方法，
旧客户端 `chat.suggest` 也继续在服务端被拒绝，不能恢复独立生成路径。
不以修改官方包、调试注入、任意内存读取或 OCR 绑定会话来代替已验证的读取接口。

## 接通后必须满足的验收条件

在取得可验证的原生只读缓存出口或原 owner 的被动事件之前，不添加一个永远没有数据的客户端功能。
后续接入必须同时验证：

1. 缓存未命中只返回空结果，绝不产生预测请求、采样、会话执行或自动发送。
2. 结果绑定当前官方身份、host、owner、会话和来源轮次；不能按标题或“最近一条”猜测归属。
3. 切换账号、会话、owner、轮次，失去连接或官方清空建议时，立即撤下旧灰字。
4. 仅空草稿显示建议；输入自己的文字、输入法组合输入和其他补全菜单不能被 Tab 接受逻辑抢占。
5. Tab 或点击接受只修改当前会话的本地草稿，零发送调用；草稿仍可编辑，发送需用户另行操作。
6. Web 与 Android 的展示值须和官方实际已有建议逐字一致；合成 fixture 只能验证客户端行为，
   不能作为已经读到官方原生建议的证明。
